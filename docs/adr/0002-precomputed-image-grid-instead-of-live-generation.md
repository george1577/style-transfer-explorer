# Precomputed image grid instead of live generation

Reference notebook 3 runs SD1.5 + a depth ControlNet img2img pipeline on a Colab T4 GPU, one image per run. The target laptop has 8 GB of RAM shared between CPU and GPU, and recent PyTorch builds crash on Apple's MPS backend on macOS 14; SD1.5 + ControlNet needs several GB of weights in memory and takes many minutes per image on CPU, so live generation there is either impossible or too slow to learn from. The app instead shows a precomputed grid: 2 reference images × 2 prompts × strength {0.3, 0.5, 0.7, 0.9} × guidance {3, 7.5, 12}, plus one image per prompt without depth conditioning (strength 0.7, guidance 7.5), 52 JPEGs at 512 px rendered once on a Colab T4 by `scripts/render_grid.py` with a fixed seed and step count, and found by the app through a manifest rather than filename conventions. A grid also teaches the parameters better than slow single shots: snapping the sliders or viewing the whole 4 × 3 grid shows each parameter's effect side by side with everything else held fixed. The parts that are cheap stay live: the depth map (Depth Anything V2 Small, ~100 MB, about a second on CPU) is computed for the reference images and for uploads, and an optional "generate live" button using the same pipeline is offered only when a GPU device is selected. We accept that learners can't try their own prompts or parameter values without a GPU, and that the grid must be re-rendered (a manual Colab step) if its prompts or axes change.
